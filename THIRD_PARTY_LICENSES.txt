THIRD-PARTY LICENSES — warpi
============================

warpi is an independent fork of Warp. This file records the third-party
dependencies of the warpi runtime distribution and the license each declares.
Read it with the project's own license files (LICENSE-AGPL, LICENSE-MIT,
LICENSE-NOTES.md) and the donor notice (standalone/DONOR-ATTRIBUTION.md).

This is a *census*, not the full per-crate license-text aggregation. It records
each dependency's declared SPDX license expression and the handful of
non-permissive or dual-licensed crates that need an election or a NOTICE. The
full texts, copyright notices, and Apache-2.0 NOTICE propagation are produced by
`cargo about generate` (see "Regenerating the authoritative file" below); no
`cargo about` was available in the environment that produced this census, which
is stated here deliberately rather than over-claiming completeness.

Scope
-----
* Rust: runtime ("normal") dependencies of the `warpi` GUI binary
  (`-p warp --features gui`). Build-script and dev-only dependencies are
  excluded, matching `about.toml` (`ignore-build-dependencies = true`,
  `ignore-dev-dependencies = true`).
* npm: production dependencies bundled with the private Pi helper
  (`standalone/pi-helper`; dev-only packages excluded).

Method
------
* Rust census, 2026-09-23, from the pinned dependency set in `Cargo.lock`:

      cargo tree -p warp --features gui --target x86_64-unknown-linux-gnu \
          --edges normal --offline --format "{p}"

  Each locked crate's declared `license` field was then read from the local
  Cargo registry source cache and the Cargo git checkouts.
* npm census: the production subset of `standalone/pi-helper/package-lock.json`
  (`"dev": true` entries excluded).

Limitations (do not over-read this file)
----------------------------------------
* The Rust census is the normal-edge closure for the Linux target with the `gui`
  feature. Windows and macOS may resolve additional platform-specific crates.
* Counts are from the dependency set at the fork commit that added this file;
  regenerate before each release.
* Declared license expressions are recorded here, not copyright notices or
  license texts. For a binary redistribution the MIT/BSD/ISC notices and the
  Apache-2.0 NOTICE must travel with the full generated file (or the shipped
  per-package files), not with this census alone.

Project licenses (for contrast)
-------------------------------
* The combined application is AGPL-3.0-only (`LICENSE-AGPL`), except
  `crates/warpui` and `crates/warpui_core`, which are MIT (`LICENSE-MIT`).
* New fork code (`crates/standalone_agent`, `standalone/**`, the packaging
  scripts) is AGPL-3.0-only. See `LICENSE-NOTES.md`.

Bundled Node.js runtime
-----------------------
The Windows installer ships a pinned Node.js 22.19.0 (`standalone\node\node.exe`;
fetched and SHA-256-verified by `script/windows/fetch-node-runtime.ps1`). Node.js
is **MIT**-licensed, and its own `LICENSE` file — shipped next to the executable
— reproduces the licenses of the components embedded in the binary (V8,
OpenSSL, libuv, ICU, and others). Keep that `LICENSE` with any redistribution of
the runtime.

Regenerating the authoritative file
-----------------------------------
The upstream pipeline already knows how to emit the full file from
`about.toml`/`about.hbs`:

    cargo about generate --workspace --manifest-path Cargo.toml \
        -c about.toml -o THIRD_PARTY_LICENSES.txt about.hbs

(see `script/prepare_bundled_resources`, which also appends the non-Cargo
licenses listed in `ADDITIONAL_LICENSES`). Re-run the npm census with
`npm ci --omit=dev` in `standalone/pi-helper` and a license checker. Replace
this census with that output before a commercial release.
